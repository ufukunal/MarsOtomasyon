- **Reservation authority:** M4.5 `StockReservationService` yeniden yazılmadı. Transaction-required ve replay-safe reserve/release/consume lifecycle, `SourceEffectIdentity` + request fingerprint payload-drift koruması, generated available projection, over-reservation guard ve PostgreSQL stock-scope concurrency serialization doğrudan yeniden kullanıldı.
- **Stable allocation lineage:** Manual sipariş satırına transient `sales_order_line.id` değerinden bağımsız UUID `logical_line_key` eklendi. `sales_order_reservation_generations` tablosu logical line + generation + product/warehouse/location/quantity + immutable StockReservation bağını saklar. Satır delete+recreate edilse bile logical allocation kimliği korunur; generation satırları PostgreSQL trigger ile append-only/one-way release davranışındadır.
- **Reserve/release davranışı:** İlk allocation aktif reservation üretir. Aynı allocation tekrar kaydedilirse yeni generation oluşmaz. Miktar, ürün, depo veya lokasyon değişirse önce eski generation terminal release edilir, ardından yeni generation reserve edilir. Tamamen yeni logical key ile replacement durumunda da iki-fazlı `release → reserve` sırası uygulanarak eski reservation'ın tuttuğu kapasite yeni allocation tarafından güvenle yeniden kullanılabilir.
- **Atomicity / guard:** Over-reservation yeni generation reserve'ini reddeder ve SalesOrder header/line delete+recreate ile önceki release dahil tüm business transaction'ı rollback eder. Resolver aktif-company Product/Warehouse/Location sahipliğini ve warehouse-location eşleşmesini doğrular; foreign/inactive allocation order state'ini değiştirmeden reddedilir.
- **Concurrency kabulü:** `UpdateSalesOrder` parent order row'unu `FOR UPDATE` kilitler; synchronizer aktif generation setini `FOR UPDATE` kilitler; M4.5 reservation projection stock-balance scope'unda rakip reserve işlemlerini serialize eder. Aynı Foundation suite içindeki `StockReservationTest` ve `StockExitGateTest` lock-timeout/competing-reservation acceptance testleri green kaldı.
- **Acceptance:** M6.3'e özel 6 test; first reserve, stable logical key + generation 1→2, identical allocation no-op, over-reservation rollback, tenant ownership, immutable generation ve full-capacity logical-key replacement release-before-reserve senaryoları green.

## - [x] M6.4 — Progress Quantities
- [x] Ordered/net-dispatched/net-invoiced/cancelled/remaining
### Tamamlanma Raporu
- **Durum:** TAMAMLANDI
- **Entry:** M6.3 squash merge `9d8498d722f7e34b9f9bdbf96904b319f04f783d`; main Foundation `32956143408` (#380) 4/4 green; PostgreSQL `295 / 2711`; Chromium `13 / 266`.
- **PR / Feature head:** `#38`; feature head `d77bf52a5813d8d32c59a6044ebd3eeb1b39e0a2`.
- **PR CI:** Foundation `32961484848` (#381) 4/4 green; PostgreSQL `299 test / 2755 assertion`; Chromium `13 test / 266 assertion`; fresh PostgreSQL schema, Pint, Larastan, frontend build ve security green.
- **Progress authority:** `sales_order_line_progress_effects` append-only effect ledger'ı ordered quantity snapshotına karşı `dispatched`, `invoiced` ve `cancelled` signed delta'larını saklar. Effect UPDATE/DELETE PostgreSQL trigger seviyesinde yasaktır; düzeltme/reversal geçmiş satırı mutate etmek yerine yeni karşıt effect ile yapılır.
- **Projection:** `sales_order_line_progress` PostgreSQL view'ı `ordered_quantity`, `net_dispatched_quantity`, `net_invoiced_quantity`, `cancelled_quantity`, `dispatch_remaining_quantity`, `invoice_remaining_quantity` ve ortak `remaining_quantity` değerlerini deterministik üretir. Ortak kalan `ordered - cancelled - GREATEST(net_dispatched, net_invoiced)` olarak türetilir; böylece sevk bağlantılı faturanın ikinci fulfillment olarak çift düşülmesi önlenir.
- **Invariant / over-operation guard:** PostgreSQL authority net dispatched/invoiced/cancelled değerlerinin negatife düşmesini engeller; `net_dispatched + cancelled <= ordered` ve `net_invoiced + cancelled <= ordered` sınırlarını zorunlu tutar. Service aynı ihlalleri validation boundary'sine taşır.
- **Exactly-once / payload drift:** `SalesOrderProgressService`, `SourceEffectIdentity` + `IdempotencyStore` + canonical `RequestFingerprint` kullanır. Aynı source effect ve aynı payload replay-safe olarak mevcut effect'i döndürür; aynı idempotency kimliğinde farklı line/type/quantity payload'ı conflict olur.
- **Concurrency:** Her progress INSERT'i owning `sales_order_lines` satırını `FOR UPDATE` kilitler. İki PostgreSQL connection'lı acceptance testinde ikinci işlem lock timeout ile serialize olur; ilk işlem commit edildikten sonra stale rakip yeniden denendiğinde over-operation guard tarafından reddedilir.
- **Draft freeze / UI:** İlk sevk/fatura/iptal progress effect'inden sonra ilgili order line PostgreSQL seviyesinde UPDATE/DELETE edilemez; manual draft edit akışı da order seviyesinde kapatılır. Sipariş detay tablosu Sipariş/Sevk/Fatura/İptal/Kalan kolonlarını projection'dan gösterir.
- **Acceptance:** M6.4'e özel 4 test; deterministic projection + immutability, transaction/idempotency/payload-drift, over-operation + signed reversal boundary ve gerçek PostgreSQL concurrency serialization senaryoları green.
- **Sınır:** M6.4 fiziksel Stock OUT, irsaliye veya fatura belgesi üretmez. M7 dispatch stock effect'lerini; M8 invoice/account/stock matrisini bu progress authority üzerine bağlayacaktır. Partial/cancel/reversal lifecycle orchestration M6.5 kapsamındadır.
- **Blocker:** Yok.
